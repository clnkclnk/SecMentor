> 用法：先快速过一遍 → 回头翻自己打过的靶场截图 → 把"操作"和"原理"对上号 → 再打综合靶场。

## 〇、先建立一张"攻击地图"

所有 Web 漏洞，按**最终危害**分成 4 类，记住这 4 类就不会乱：

| 类别 | 一句话 | 包含漏洞 | 你的靶场锚点 |
|---|---|---|---|
| **① 偷数据** | 把不该看的数据拿出来 | SQL 注入、XXE、未授权访问 | MySQL `/vuln/users` 拖库 |
| **② 夺权限（RCE）** | 在服务器上执行我的命令 | 文件上传、文件包含(LFI)、命令注入、反序列化、Redis 写马 | LFI `whoami=刘帅超` |
| **③ 骗人/冒充** | 利用别人的身份或浏览器 | XSS、CSRF、SSRF | SSRF 打内网 FLAG |
| **④ 绕认证** | 绕过登录/权限检查 | 弱口令、爆破 | MySQL `admin/123456` |

**核心规律**：①和②是"服务器侧泄露/失控"，③是"借别人身份"，④是"进门那关没守住"。

## 二、基础设施（P1~P3，是看懂漏洞的前提）

### 2.1 网络基础
- **IP / 端口 / DNS**：IP 是服务器地址，端口是服务器上的"门"（每个服务开一扇），DNS 把域名翻译成 IP。
- **关键端口**：HTTP `80`、HTTPS `443`、Redis `6379`、MySQL `3306`、SSH `22`。
- **TCP / HTTP 关系**：TCP 是传输层（保证数据到），HTTP 是应用层（规定数据格式）。HTTP 跑在 TCP 之上。
- **进程/文件/权限**：服务器上每个服务是一个进程；它能读哪些文件取决于运行它的用户权限。

### 2.2 Linux 与工作环境
- 基础命令：`ls` `pwd` `cd` `touch` `cat` `curl`。
- Docker：隔离的实验室环境，`docker run hello-world` 验证可用。

### 2.3 Web 前置（看懂漏洞必会）
- **HTTP 报文**：请求 = `方法 路径 头 体`；响应 = `状态码 头 体`。
  - 方法：`GET`（取数据，无体）、`POST`（提交数据，有体）。
  - 状态码：`200` 成功、`301/302` 跳转、`401` 未授权、`403` 禁止、`404` 找不到、`500` 服务器错。
- **Cookie / Session**：
  - Cookie：存在**浏览器**里的小纸条，每次请求自动带上。
  - Session：存在**服务器**里的大账本，Cookie 里只放一个 SessionID 当取号。
  - 登录态本质：服务器靠 SessionID 认出"这是已登录的张三"。
- **代理抓包（Burp）**：让浏览器流量先过 Burp，你能看/改每个请求（中间人）。这是你的"显微镜"。
- **浏览器 DevTools（F12）**：Network 看请求、Application 看 Cookie、Console 执行 JS。
- **HTTPS / TLS**：加密传输 + 证书验证身份。证书不对 = 中间人可能正在偷看。

## 三、① 偷数据类

### 3.1 SQL 注入（SQL Injection）
- **原理**：用户输入被**拼进 SQL 语句**，导致输入变成了 SQL 代码（数据当代码执行）。
- **关键技巧**：
  - 单引号 `'` 越狱：原语句 `'SELECT * FROM u WHERE name='+输入+'`，输入 `admin'` 把引号提前闭合，破坏语法 → 报错暴露结构。
  - 注释 `--`：吃掉后面的原 SQL。
  - 恒真 `OR 1=1`：让 WHERE 条件永远成立 → 返回全部数据。
  - `UNION SELECT`：把查询结果"拼"到自己想查的表上（偷密码表）。
- **靶场五关【锚点·你打过】**：报错信号 → 逻辑运算 `AND 1=1` → 登录绕过 `admin'--` → UNION 联合查询偷数据 → 参数化防御验证。
- **真实挖法**：找所有"带参数的地方"（URL `?id=`、`POST` 表单、`Cookie`、请求头），逐个塞 `'` 看是否报错/行为异常。
- **防御**：**参数化查询（预编译）**——SQL 模板和参数分开传，参数永远不被当代码。这是根治手段。

### 3.2 XXE（XML 外部实体注入）
- **原理**：XML 支持"外部实体" `<!ENTITY x SYSTEM "file:///etc/passwd">`，解析时把文件内容塞进实体；`SYSTEM "http://内网"` 还能发请求。
- **本质**：**读文件（路径穿越） + 发请求（SSRF）的合体**。
- **靶场【锚点·你打过】**：用 lxml 解析器，4 场景——
  - `file:///` 读系统 hosts 文件
  - 读靶场秘密配置（DB_PASSWORD / API_KEY）
  - `http://` 打内网服务拿到 `FLAG{xxe_reached_internal_service_2026}`
- **真实挖法**：找接收 XML 的接口（SOAP、上传 XML、某些 API），发带外部实体的 XML。
- **防御**：禁用外部实体（`resolve_entities=False` + `no_network=True`）。

### 3.3 未授权访问（Redis / MySQL）
- **原理**：该检查身份的地方**没检查**——要么服务本身无密码，要么接口忘了加鉴权。
- **Redis 版【锚点·你打过】**：
  - 默认无密码 → `redis-cli` 直接连 → `KEYS *` 列光所有键 → `GET flag` 读机密。
  - 最危险升级：无密码 + 可写文件 → `CONFIG SET dir` + `CONFIG SET dbfilename` + `SAVE` 生成 WebShell → 夺权（见 4.5）。
- **MySQL 版【锚点·你打过】**：
  - 弱口令 `admin/123456` 直接登录后台。
  - 接口 `/vuln/users` **不验证 token** → 浏览器直接打开就返回全部用户明文密码。
  - `/vuln/secret?k=flag` 直接拿走 FLAG。
- **真实挖法**：`nmap` 扫出 6379/3306 → 试匿名连 / 试弱口令 → 拖库。
- **防御**：Redis 加 `requirepass` + `bind 127.0.0.1` + `protected-mode`；接口统一加鉴权中间件。

## 四、② 夺权限类（RCE 全家福）

> **RCE = Remote Code Execution，远程代码执行**。下面 5 种漏洞，终点都是"在服务器上跑我的命令"。记住它们"入口不同、终点相同"。

### 4.1 文件上传
- **原理**：上传 `.py`/`.php` 文件，服务器当**程序**执行 → 这就是 WebShell（远程控制后门）。
- **靶场【锚点·你打过】**：Level1 传 `shell.py` 落地 → 访问它就触发 `whoami`；Level2 白名单把 `.py` 拦了，`.jpg` 能传但随机重命名无法执行。
- **防御三件套**：扩展名白名单 + 随机文件名 + 存到不可执行目录。

### 4.2 文件包含（LFI / RFI）
- **原理**：`include(用户控制的路径)` → 把指定文件当**代码**加载执行。
- **LFI（本地包含）**：包含服务器本地文件。若文件内容是你控制的（如上传的 shell），就 RCE。
  - 靶场【锚点·你打过】：`page=webshell` 触发 `whoami=刘帅超`；`../lfi_secret.py` 读到数据库密码。
- **vs 路径穿越**：穿越是"**读**文件"（只看到内容），包含是"**执行**文件"（当成代码跑）。危害差一个量级。
- **防御**：包含路径白名单，禁止 `../` 和用户控制路径。

### 4.3 命令注入（Command Injection）
- **原理**：用户输入拼进命令行，分隔符让输入从"参数"变成"一条新命令"。
- **五种分隔符**：`;` `|` `&` `&&` `` ` `` `$( )`
  - `;` 前令执行完再执行后面的（不管前面成败）
  - `|` 管道，把前面输出给后面
  - `&&` 前面成功才执行后面
  - `` `cmd` `` 和 `$(cmd)` 把命令结果替换进原处
- **靶场【锚点·你打过】**：`ping` 输入框里填 `8.8.8.8; whoami` → 服务器先 ping 再执行 `whoami` → 拿到 `刘帅超`。
- **真实挖法**：找"命令类"功能（ping、nslookup、导出、邮件发送），尝试插分隔符。
- **防御**：参数化（`shell=False` 直接传参数数组，不经 shell）+ 输入白名单（只允许 IP 格式等）。

### 4.4 反序列化（Deserialization）
- **原理**：序列化 = 把对象变成可传输的字符串；反序列化 = 还原对象。**还原的瞬间会自动执行对象里的代码**。若攻击者能伪造这个字符串，就能塞恶意代码让服务器还原时执行。
- **靶场【锚点·你打过】**：Python `pickle` 用 `__reduce__` 构造恶意对象 → 服务器 `pickle.loads()` 还原瞬间执行 `whoami` → `刘帅超`。Level2 只允许 JSON 纯数据 → 字节被拒，未执行任何代码。
- **为什么阴险**：看起来只是"传了段数据"，毫无攻击痕迹，最难发现。
- **真实挖法**：找反序列化入口（Cookie、API 对象参数），替换成自己生成的恶意 payload。
- **防御**：用 JSON 等纯数据格式 + 对数据做签名校验（防篡改）。

### 4.5 Redis 写马（夺权升级路径，串起 3.3 + 4.1）
- **完整攻击链**：Redis 无密码 → `CONFIG SET dir /网站目录` → `CONFIG SET dbfilename shell.php` → `SET x "<?php ...?>"` → `SAVE` → 网站目录下生成 WebShell → 访问它 RCE。
- **记忆点**：这是"未授权访问"升级成"RCE"的经典跳板，把 ①偷数据 和 ②夺权限 连起来了。

## 五、③ 骗人 / 冒充类

### 5.1 XSS（跨站脚本）
- **原理**：用户输入的 JS 被**浏览器**执行（数据当代码，但在**客户端**——危害是攻击其他访问者）。
- **三类**：
  - 反射型：恶意脚本在 URL 里，受害者点链接触发。
  - 存储型：脚本存进数据库（如留言板），别人打开页面就中招。
  - DOM 型：前端 JS 直接处理恶意输入，不经过服务器。
- **靶场【锚点·你打过】**：4 关（`<script>alert(1)</script>`、`<img onerror=...>`、窃取 Cookie）。
- **危害**：盗 Cookie 冒充用户、钓鱼、蠕虫。
- **防御**：输出转义 + CSP（限制能执行的脚本源）+ HttpOnly（Cookie 不让 JS 读）。

### 5.2 CSRF（跨站请求伪造）
- **原理**：骗**浏览器**带着受害者的 Cookie，以受害者身份发一个请求（利用已登录态）。
- **靶场【锚点·你打过】**：构造隐藏表单自动提交 → 趁 alice 已登录，静默转走她 ¥3000；bob 账户因有 Token 被拦。
- **vs SSRF（重点区分）**：
  - CSRF = 骗**浏览器**（受害者的客户端）
  - SSRF = 骗**服务器**（借服务器身份发请求）
- **防御**：CSRF Token（每次请求带随机值，攻击者造不出）+ SameSite Cookie + 敏感操作二次确认。

### 5.3 SSRF（服务端请求伪造）
- **原理**：让**服务器**替你发请求，访问它才能访问的内网资源（借服务器身份）。
- **靶场【锚点·你打过】**：
  - `/secret` 拿到 FLAG
  - `/meta` 泄露云元数据（云密钥 `AKIA_`）
  - `/redis` 操作本机 Redis 数据库
- **三大攻击目标**：本机服务（127.0.0.1）、云元数据（169.254.169.254 拿临时凭证）、内网扫描（打其他内网机器）。
- **真实挖法**：找"服务器会去 fetch 一个 URL"的功能（头像抓取、网页预览、Webhook），把 URL 改成内网地址。
- **防御**：URL 白名单（只允许公网特定域名），禁止 127.0.0.1 / 内网段。

## 六、④ 绕认证类

### 6.1 弱口令 / 爆破
- **弱口令**：管理员用 `123456`/`admin`/`root` → 一猜就中【锚点·MySQL `admin/123456`】。
- **爆破**：用字典批量试用户名密码（Burp Intruder 自动化）。
- **防御**：强密码策略（长度+复杂度）+ 失败锁定 + 验证码 + 多因素认证。

## 七、P9 中间件漏洞共性（串起全篇）

### 7.1 三大共性模式
| 模式 | 表现 | 例子 |
|---|---|---|
| 默认无密码/未授权 | 装好就能连、接口无鉴权 | Redis 无密码；MySQL `/vuln/users` |
| 弱口令 | 管理员用简单密码 | MySQL `admin/123456` |
| 危险功能暴露 | 能写文件/执行命令的接口对外 | Redis `CONFIG SET dir` 写马 |

### 7.2 你打过的两个中间件
- **Redis**：服务层错误（无密码）→ 直接连 → 拖库/写马。
- **MySQL**：接口层错误（无鉴权 + 弱口令）→ 拖库/登后台。
- **一句话**：都是"该检查身份的地方没检查"，区别在错误发生在哪一层。

## 九、真实挖洞 vs 靶场的差距（回应你的困惑）

- **靶场**：把"发现服务 + 判断漏洞"藏起来了，直接给你页面和输入框 → 练的是"武器怎么用"。
- **真实**：你要先 `nmap` 扫端口 → 判断服务/版本 → 试各类 payload → 绕过 WAF/防火墙 → 组合利用链。
- **靶场的价值**：建立"攻击直觉"。以后看到 3306 端口大脑自动问"弱口令吗？能未授权连吗？"；看到 `include($_GET['page'])` 自动想"能 LFI 吗？"——这反应速度就是练出来的。
