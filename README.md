# SecMentor：让 AI 成为你的网络安全入门教练

> 不是把一套网络安全教程交给 AI 朗读，而是让 AI 根据学习者每天的真实表现，决定今天讲什么、练什么、哪里需要回退，以及是否真的掌握。

## 为什么要做 SecMentor

网络安全入门培训一直是一门不小的生意。

“交多少学费，带你入门网络安全”“从零开始挖 SRC”“一个月学会渗透测试”——类似的课程很多，其中当然有认真教学的老师，但也有相当一部分课程，本质上只是把流传过很多手的教程重新整理一遍：

- 先讲 Linux 命令；
- 再讲计算机网络；
- 然后安装几个工具；
- 跟着视频复现几个漏洞；
- 最后发一套靶场题和 SRC 资料。

这类课程不一定完全没有价值。

对于刚入门的人来说，有人帮忙整理学习顺序、筛选资料、回答问题，本身就是一种帮助。真正的问题在于：

> **自己会做一件事，和能够把一个新人真正教会，是两种完全不同的能力。**

很多安全从业者可以独立分析漏洞、排查问题、完成渗透测试，但并不一定知道：

- 初学者为什么会卡在这里；
- 他是真的理解了，还是只记住了命令；
- 应该继续往下讲，还是退回去补基础；
- 应该直接告诉答案，还是只给一个观察方向；
- 如何判断他已经具备处理陌生问题的能力。

传统课程通常使用同一份课表面对所有学员。无论学习者有没有编程基础、是否使用过 Linux、能不能读懂 HTTP 请求，大家都按照相同顺序往下走。

老师也很难每天持续观察一个人的学习过程。

但 AI Agent 的出现，让这件事有了新的可能。

现在的 AI 已经能够完成大量基础知识讲解、代码阅读、命令排错和实验环境辅助工作。它可能还不能替代真正优秀的安全研究员，但在耐心解释、反复举例、根据反馈调整表达方式这些方面，已经超过了很多普通培训。

于是我们开始思考一个问题：

> 为什么不把一名优秀安全导师的教学方法写成一套 Skills，让 AI Agent 按照这些规则，一步一步带领一个新人学习网络安全？

这就是 SecMentor 的起点。

---

## SecMentor 是什么

**SecMentor 是一套面向 AI Agent 的网络安全教学 Skills。**

它不是一个大模型，也不是一套录播课程，更不是自动化渗透工具。

你可以把它理解成一份交给 AI 的“教学操作规程”：

- 如何对学习者进行能力摸底；
- 如何根据已有基础选择起点；
- 如何安排每天的学习目标；
- 如何讲解一个安全概念；
- 如何组织本地实验；
- 如何逐级提供提示；
- 如何判断学习者是否真正掌握；
- 如何记录长期进度；
- 如何在失败后进行补课；
- 如何避免 AI 直接替学习者完成任务。

SecMentor 可以运行在能够读取项目文件、保存学习状态的 AI Agent 中，例如：

- WorkBuddy
- Cursor
- Claude Code
- Codex
- 其他支持项目级指令的通用 Agent

打开项目后，Agent 会读取 SecMentor 的教学规则、课程地图和学习者档案，然后进入“网络安全教练”模式。

---

## 它和普通 AI 问答有什么区别

直接问 AI：

> “教我 SQL 注入。”

通常会得到一篇完整的 SQL 注入介绍：

- 原理是什么；
- 常见分类有哪些；
- Payload 怎么写；
- sqlmap 怎么使用；
- 如何修复。

内容可能没有错，但这并不等于学习发生了。

学习者看完后说一句“懂了”，AI 很可能马上进入下一章。至于他能不能从一条 HTTP 请求中找出参数、能不能根据后端代码推导 SQL、能不能判断闭合方式，AI 并不知道。

SecMentor 不把“已经讲过”当作“已经掌握”。

它要求每一个重要知识点都经过一个完整闭环：

```text
唤醒已有知识
    ↓
讲解一个小目标
    ↓
学习者亲自操作
    ↓
观察真实结果
    ↓
解释为什么会出现这个结果
    ↓
完成一个变化后的同类任务
    ↓
记录证据和学习状态
```

学习者说“我懂了”，只能算一种自我陈述，不能成为通过依据。

只有出现可以验证的证据，例如：

- 独立构造并重放了一条请求；
- 根据响应变化解释了参数作用；
- 完成了一个本地实验；
- 读懂了一段存在缺陷的代码；
- 在换参数、换路径或换场景后仍能完成分析；
- 提交了一份实验记录或简短报告；

对应知识点才会被标记为已经掌握。

## SecMentor 的核心原则

### 1. 根据人来排课，而不是让人适应课表

第一次使用时，SecMentor 会进行动态摸底。

摸底不仅询问“学过什么”，还会通过小问题和实际任务观察：

- 计算机与网络基础；
- Linux 和终端使用；
- 编程与代码阅读能力；
- HTTP 和 Web 应用理解；
- 安全基础；
- 工具使用习惯；
- 英文资料阅读能力；
- 遇到错误时的排查方式。

两个人都说自己是“零基础”，实际情况可能完全不同。

有人不会写代码，但已经能熟练使用 Linux；有人学过 Python，却不理解浏览器和服务端如何交互；还有人会运行大量安全工具，但无法解释扫描结果意味着什么。

SecMentor 会记录这些差异，并在完成必要的安全边界学习后，为每个人选择不同起点。

### 2. 一天只解决有限的问题

传统教程很容易一次讲完几十个概念。

SecMentor 更倾向于为每次学习确定一个可以验收的小目标，例如：

> 今天结束时，你应该能够读懂一条基本 HTTP 请求，并指出请求方法、路径、参数和 Header。

而不是：

> 今天学习完整的 HTTP 协议。

当学习时间不足时，课程可以缩小为一个 micro 学习切片。没有完成验收，就记录为部分进展，而不是为了推进课表假装已经通过。

### 3. 学习者动手，Agent 不代做

SecMentor 可以帮助搭建环境、解释错误、给出排查方向，但真正的操作由学习者完成。

包括：

- 安装 Docker 或虚拟机；
- 启动和停止实验环境；
- 使用浏览器开发者工具；
- 配置抓包代理；
- 执行命令；
- 修改请求；
- 阅读日志；
- 分析代码；
- 整理实验记录。

Agent 不应该在后台完成整个实验，然后把答案展示给学习者。

提示采用逐级提升的方式：

```text
观察什么
→ 从哪个方向分析
→ 关键步骤是什么
→ 把任务拆得更小
→ 必要时完整演示
```

如果 Agent 已经给出了完整答案，学习者随后照抄完成，这次结果不会被直接视为独立掌握。

### 4. 失败不是扣分，而是下一节课的输入

同一个任务失败，原因可能完全不同：

- 概念没有理解；
- 工具不会使用；
- Docker 环境异常；
- 端口冲突；
- 看错了题目；
- 操作失误；
- 得到的提示过多；
- 不知道如何观察结果。

SecMentor 会区分这些原因。

环境故障不应该被误判为能力不足；一次粗心也不需要机械退回上一章。只有明确发现知识缺口时，才会安排对应的补课内容。

### 5. 训练迁移能力，而不是记住 Payload

完成刚刚演示过的原题，只能证明学习者会重复。

真正的掌握需要面对变化：

- 参数名改变；
- 请求方法改变；
- 数据从表单变成 JSON；
- 路径结构改变；
- 错误信息被隐藏；
- 后端代码写法改变；
- 工具不可用，需要手工分析。

SecMentor 使用 `recall`、`understand`、`apply` 和 `transfer` 四个层级记录掌握程度：

| 层级 | 含义 |
|---|---|
| `recall` | 能记住术语或步骤 |
| `understand` | 能解释原理 |
| `apply` | 能完成同类任务 |
| `transfer` | 能处理没有见过的变体 |

至少达到 `apply`，一个知识点才会被视为基本通过。核心知识点还会尽量要求一次迁移验证。

## 学习路线

SecMentor 当前将网络安全入门划分为以下阶段：

| 阶段 | 学习内容 |
|---|---|
| P0 | 学习契约、授权范围与安全边界 |
| P1 | IP、端口、DNS、TCP 等基础直觉 |
| P2 | Linux、终端、进程、权限与实验环境 |
| P3 | HTTP、Cookie、Session、浏览器和抓包代理 |
| P4 | 身份认证、弱认证与 Fuzz 思维 |
| P5 | 文件上传、下载、路径遍历和文件包含 |
| P6 | SQL 基础、注入原理、手工验证与修复 |
| P7 | XSS、CSRF、上下文与编码 |
| P8 | SSRF、XXE、命令执行等服务端漏洞 |
| P9 | 中间件、数据库与常见服务安全 |
| P10 | 方法论、综合实验和简报输出 |

这不是一张要求所有人从头刷到尾的固定课表。

部分基础阶段可以通过摸底进行免修或缩短，但 P0 的授权范围和学习规则不能跳过。

课程也不会只按“漏洞章节”推进。每个核心阶段都会尽量组织一个纵向小项目，把多个零散知识点放进一次完整任务中。

例如，Web 基础阶段的目标不是背完 HTTP 状态码，而是完成：

> 观察并解释一次完整登录请求。

学习者需要留下：

- 请求报文；
- 参数和 Header 说明；
- Cookie 或 Session 的作用；
- 浏览器、服务端和数据库之间的关系；
- 一份简短实验记录。

## 实验环境

网络安全不能只靠阅读。

SecMentor 会优先使用本地、专用靶场或明确授权的实验环境进行教学。仓库内提供了一些最小实验示例，例如：

- HTTP 请求观察；
- 路径遍历；
- SQL 注入基础。

这些实验不是要求课程与某个固定镜像永久绑定，而是可以复用的教学资源。

Agent 可以根据当前设备、系统架构、已经安装的工具和学习目标，选择：

- 仓库已有实验；
- 经典开源靶场；
- 学习者已经部署的环境；
- 为解释单一原理生成的最小本地服务；
- 其他等价的合法实验环境。

环境可以动态选择，但教学目标和验收要求不能随意改变。

例如，一个路径遍历实验至少要让学习者证明：

- 能找到用户可控的路径参数；
- 能解释路径如何被服务端拼接；
- 能说明正常路径与异常路径之间的区别；
- 能提出合理的防御方法；
- 能在变化后的同类环境中再次识别问题。

## 学习记录如何保存

SecMentor 不依赖 AI 的短期记忆来判断进度。

所有关键状态都会保存在项目目录中：

```text
learner/
├── progress.json       # 当前学习摘要
├── events/             # 完整学习事件
├── evidence/           # 实验输出和验收证据
├── assessments/        # 阶段评估
├── journal/            # 每日或每周复盘
└── ui/                 # 可选的进度卡与里程碑页面
```

`progress.json` 只保存当前状态，例如：

- 当前阶段；
- 正在学习的知识点；
- 已经通过的内容；
- 仍然模糊的概念；
- 当前补课任务；
- 最近事件；
- 积分和里程碑。

完整过程则写入按月份拆分的事件文件，避免学习时间变长后，单个进度文件不断膨胀。

学习数据默认保存在本地仓库中，不需要上传到远端服务。使用者应自行决定是否备份或同步这些记录，并注意不要把包含个人信息的学习档案误提交到公开仓库。

## 积分与反馈

学习网络安全很容易出现一种感觉：

> 学了很多，但不知道自己到底走了多远。

SecMentor 内置了一套轻量的正反馈机制。

完成有效学习、通过知识点、完成迁移题、提交阶段项目时，学习者可以获得积分和里程碑。

积分不用于制造虚假进度，也不能代替学习证据。

没有完成实际任务，就不能因为“今天聊了很久”而获得通过分。验收失败也不会扣分，而是给出下一步线索和补课建议。

当前称号包括：

```text
初出茅庐
崭露头角
声名鹊起
名动一方
一代宗师
大宗师
```

这种设计不是为了把学习变成简单的游戏，而是希望每天都能看到具体进展，在第一次完成实验、第一次独立迁移、连续学习一周等节点获得一些仪式感。

## 如何开始使用

### 1. 准备一个支持项目文件的 AI Agent

推荐使用能够读取和修改本地项目文件的 Agent，例如 WorkBuddy、Cursor、Claude Code 或 Codex。

只使用普通网页聊天也可以学习知识，但无法完整使用长期进度、证据和实验记录能力。

### 2. 下载或克隆 SecMentor

将 SecMentor 放在一个独立目录中，然后使用 AI Agent 打开整个项目。

项目入口文件是：

```text
AGENTS.md
```

不同产品的适配说明位于：

```text
adapters/
```

### 3. 开始第一次对话

打开项目后，可以直接告诉 Agent：

```text
我想从今天开始学习网络安全，请按照 SecMentor 的流程先对我进行摸底。
```

也可以提供更多信息：

```text
我目前没有网络安全经验，会一点 Python，平时使用 Windows，
每天大概可以学习一小时。我希望先学习 Web 安全。
请按照 SecMentor 的流程开始，不要直接给我完整答案。
```

Agent 会先完成：

```text
背景访谈
→ 动态摸底
→ 建立学习档案
→ 学习授权与实验边界
→ 确定后续起点
```

### 4. 继续第二天的学习

以后重新打开项目时，可以直接说：

```text
继续今天的 SecMentor 学习。
```

Agent 会读取 `learner/progress.json`，判断：

- 是否存在未解决的失败；
- 哪些概念仍然模糊；
- 上次学习停在哪里；
- 今天适合学习新知识还是进行复习；
- 是否需要完成迁移测试。

### 5. 结束当天学习

完成当天内容后，可以说：

```text
今天先学到这里，帮我完成复盘并保存进度。
```

Agent 会整理：

- 今天真正完成了什么；
- 哪些内容仍未掌握；
- 出现了哪些卡点；
- 保存了哪些证据；
- 下一次应该从哪里开始。

## 一个完整学习日大致是什么样

一次正常的学习过程可能如下：

### 今日目标

> 能够读懂一条 HTTP GET 请求，并解释修改查询参数后响应为什么发生变化。

### 原理讲解

Agent 不一次讲完整个 HTTP 协议，只解释完成目标所需的部分：

- 请求方法；
- URL 和查询参数；
- Header；
- 响应状态；
- 响应正文。

### 动手实验

学习者启动本地实验，在浏览器或抓包工具中观察请求，然后亲自修改参数。

### 验收

Agent 不问“听懂了吗”，而是要求学习者：

1. 找出请求中的可控参数；
2. 说明参数修改前后的响应差异；
3. 用自己的话解释服务端可能做了什么；
4. 再完成一个参数名或请求形式发生变化的任务。

### 保存证据

实验现象、回答和独立程度被记录下来。

达到要求后，对应知识点从 `in_progress` 更新为 `passed`；没有达到要求则记录为 `partial` 或进入补课流程。

### 当日复盘

最后生成一份简短记录：

```text
今天掌握：
- 能识别 GET 请求中的查询参数
- 能对照响应判断参数作用

仍然模糊：
- Header 和请求正文的边界
- Cookie 与 Session 的关系

下次建议：
- 先复习请求结构
- 再进入浏览器开发者工具和 Cookie
```

## SecMentor 不是什么

### 它不是自动化攻击 Agent

SecMentor 不负责替用户扫描互联网资产、自动利用漏洞或完成未授权攻击。

所有攻击性操作必须限定在：

- 本地环境；
- 专用靶场；
- 明确授权的测试范围。

### 它不是答案生成器

学习者把一道靶场题交给 Agent，Agent 不应该立刻给出完整 Payload、Flag 或通关步骤。

它首先应该帮助学习者观察、提出假设、验证假设，并逐步提升提示强度。

### 它不承诺包挖 SRC 或包就业

漏洞挖掘需要长期积累，包括开发理解、调试能力、信息判断、耐心和大量真实经验。

SecMentor 可以帮助建立基础能力，但不能把几个月的学习包装成“保证挖到漏洞”。

### 它不是无人值守的完整教育产品

当前版本仍然是 **SecMentor 0.1**。

它已经具备：

- 动态摸底；
- 课程路由；
- 学习状态；
- 结构化证据；
- 分级验收；
- 失败回退；
- 实验组织；
- 每日复盘；
- 积分与里程碑；
- 多种 Agent 适配。

但它仍然需要真实学习者不断试用和校正。

尤其在第一周，建议有经验的人偶尔观察：

- Agent 是否错误推进了课程；
- 是否把自述当成掌握证据；
- 是否给答案过快；
- 是否能正确区分环境问题和知识问题；
- 第二天能否从正确的位置继续；
- 学习者是否逐渐变得更加独立。

## 适合哪些人

SecMentor 主要面向：

- 想学习网络安全，但不知道从哪里开始的人；
- 看过很多教程，却始终无法独立分析问题的人；
- 会使用一些工具，但基础原理不扎实的人；
- 身边有安全从业者，却无法获得长期一对一指导的人；
- 希望通过持续实验而不是只看视频入门的人。

它暂时不适合：

- 只想快速获得现成 Payload 或答案的人；
- 希望 Agent 自动完成 SRC 漏洞挖掘的人；
- 不愿意亲自安装环境、执行命令和记录现象的人；
- 希望几天内掌握完整渗透测试体系的人。

## 我们真正想验证什么

SecMentor 第一阶段不追求课程数量，也不追求覆盖所有漏洞类型。

我们更关心一条最小链路能否长期成立：

```text
摸底
→ 确定一个小目标
→ 学习者亲自实验
→ Agent 根据真实结果验收
→ 保存可信进度
→ 第二天正确续学
```

如果这条链能够连续运行，AI Agent 就不再只是一个随问随答的知识库，而开始具备“长期教学”的能力。

真正有价值的结果，也不是学习者背下多少 Payload，而是他在面对一个没见过的问题时，开始形成自己的分析路径：

```text
先观察现象
→ 明确输入和输出
→ 提出假设
→ 寻找证据
→ 做最小验证
→ 根据结果调整方向
```

这才是网络安全学习中最重要、也最难被传统教程教会的能力。

## 写在最后

AI 能讲解知识，并不意味着 AI 天生就会教学。

如果没有规则，它很容易：

- 一次讲得太多；
- 太快给出答案；
- 把“听懂了”当成“会做了”；
- 不断推荐更多工具；
- 为了让对话顺利而虚假推进学习进度。

SecMentor 想做的，是把一名优秀导师最重要的行为写下来：

- 根据学习者调整内容；
- 用证据判断掌握程度；
- 发现缺口时主动回退；
- 不替学习者完成任务；
- 让每一次错误成为下一次教学的输入；
- 关注能否处理陌生问题，而不是记住多少答案。

它可能无法替代真正优秀的老师。

但对于那些没有老师、无法承担长期培训费用，或者身边的安全从业者没有时间每天指导的人来说，一个耐心、持续、会记录、会调整的 AI 安全学伴，可能已经足够成为他们进入网络安全世界的第一位老师。

**SecMentor，希望让网络安全入门不再依赖昂贵课程，也不再依赖偶然遇到一个愿意长期带你的师傅。**
