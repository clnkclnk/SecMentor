## 钩子

Web 站里，腰牌是 Cookie；云里，腰牌是 **身份（Identity）**——用户、角色、服务账号、临时凭证。  
云安全挖洞最赚的一刀，常常不是「远程命令」，而是：**拿到一把不该拥有的钥匙，合法 API 替你干活**。  
所以云猎人第一课不是背产品名，而是问：谁能对什么资源做什么动作？

（停：等学员说「继续」）

## 片 1 · 三件套：谁 / 能做啥 / 对哪

用江湖话先钉死：

| 概念 | 白话 |
|------|------|
| Principal（主体） | 谁（人、角色、应用） |
| Action（动作） | 能干啥（读对象、建库、AssumeRole…） |
| Resource（资源） | 对哪把粮仓（某个 bucket、某台实例） |

策略（Policy）就是把三件套写成规矩。  
**过度权限** = 厨房小二居然有开金库的钥匙——配置错误里的常客。

（停：等学员说「继续」）

## 片 2 · 猎人常盯的「掉钥匙」现场

不必一次学完所有云产品，先认这几类事故现场：

1. **长期密钥进仓库 / 前端 / 日志**（Access Key、Service Account JSON）  
2. **角色信任关系写太松**（谁都能 AssumeRole）  
3. **公开可写/可读的存储**（桶策略、ACL）  
4. **元数据或 CI 里泄临时凭证**（下一课细讲）

Hunter 节奏：**先找钥匙痕迹 → 在授权范围内验证影响 → 写清 blast radius（能碰哪些资源）**。  
别一上来列 40 个工具。

## 片 3 · 今日只练「读策略的眼睛」

给你任意一段 IAM/桶策略（自己账号控制台截图、或公开错误配置案例文章里的示例），练三问：

1. 主体是谁？  
2. 允许了哪些 Action？  
3. Resource 是 `*` 还是具体 ARN？`*` 意味着什么风险？

答得出来，比背「IAM 最佳实践十条」更接近实战。

（停：等学员说「继续」）

## 今日微任务

任选其一（必须在自己有权的环境或公开文档示例上）：

**A.** 在自己的云账号（或厂商文档示例）找一条策略，用「谁/动作/资源」三列表格拆开发我。  
**B.** 假设某 CI 日志里出现了 `AKIA...` 形状的密钥：你的**下一步合法动作**是什么（轮换、范围评估、报告）？写 5 行以内计划。

不要对未授权账号做枚举或调用。

## 过关一句话

能用「谁 · 能做啥 · 对哪」拆一条策略，并说出云挖洞为何常从**身份与密钥**开始。
