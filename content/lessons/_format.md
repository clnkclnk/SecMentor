# 示范小课格式（给写课的人 / Agent）

每课一个 Markdown。Agent **按「片」朗读讲解**，每片结束等学员「继续」，禁止一次贴完全文。

## 文件头

```yaml
---
id: L02-http-letter
title: HTTP：把请求当成一封信
covers: [http-basics, burp-intro]
persona: [beginner, practitioner, hunter]
minutes: 15
lab_hint: labs/http-observation 或任意可访问的 HTTP 服务
fun_tone: wuxia  # 可用江湖比喻，勿油腻、勿侮辱
---
```

## 正文结构（必须按序）

1. `## 钩子` — 30 秒故事/比喻，勾住「为什么今天要学这个」  
2. `## 片 1` … `## 片 N` — 每片只讲一个点；片末写 `（停：等学员说「继续」）`  
3. `## 今日微任务` — 一个可在 10～20 分钟完成的动手点  
4. `## 阅读（可选，最多 1 条）` — 链接 + 读哪一节  
5. `## 过关一句话` — 学员能复述什么才算这课过  

## 寓教于乐（学 sqlsec 的「有靶场、有故事」，不是整活）

参考 [sqlsec 课程体系](https://course.sqlsec.com/)：先建立心智模型，再上练习；理论与可动手验证绑在一起。

- 用**生活/江湖比喻**解释机制（信差、腰牌、账房），再映射到术语  
- 每课至少有一个「啊原来如此」的转折  
- 可以夸学员进步，但要具体（对齐 motivation）  
- 禁止：恐吓式「不学这个就找不到工作」、营销话术、倾倒工具清单  

## Agent 使用规则

1. 查 `catalog.yaml` 找到当前 topic / planned_topics 对应课。  
2. **只输出钩子 + 片 1**，等「继续」。  
3. 全部片讲完再给微任务。  
4. 无对应示范课时：可临场编，但须遵守同一「片」结构；编完可建议沉淀进 `content/lessons/`。  
5. 示范课是**讲稿**，不是替代合法边界与证据要求。
