## 钩子

账房有一本流水账，查账时本该只问：「姓张的客人住几号？」  
若有人把问句改成：「姓张的；顺便把金库账本也给我抄一份——」  
而账房又傻乎乎把整句当指令执行——这就是 **SQL 注入**：本该是「数据」的输入，被拼进语句后变成了「代码」。  
名字吓人，本质是一句：**拼接字符串当查询，等于把笔交给陌生人。**

（停：等学员说「继续」）

## 片 1 · 最小心智模型（先别堆 Payload）

伪代码直觉：

```text
sql = "SELECT * FROM users WHERE name = '" + 用户输入 + "'"
```

若用户输入是：`张三' OR '1'='1`  
整句语义可能被改成「查出所有人」。  

今天目标不是背 50 条 payload，而是：

1. 看出「哪里把输入拼进 SQL」  
2. 会用**合法靶场**验证「多返回了不该看的数据」  
3. 知道修法方向：参数化查询 / ORM 绑定，而不是「过滤单引号了事」

（停：等学员说「继续」）

## 片 2 · 怎么「温柔地」确认有问题

在练武场里，常见信号（出现一个就值得深挖）：

- 正常输入 OK，带 `'` 就报错或页面异常  
- 逻辑运算符让结果集合突然变大  
- 布尔题：真条件与假条件页面明显不同  

工具可以帮你加速，但口述时要说得清：**哪一个参数、怎样改变了查询语义**。  
Hunter 挖洞时也一样：报告里写「参数 X 未绑定 → 可布尔盲注」，比贴一串神秘 payload 更像专业。

（停：等学员说「继续」）

## 片 3 · 防御一句话（学攻也要会说防）

- **正道**：预编译 / 参数绑定，输入永不进语句结构  
- **旁门**：转义、WAF——有用，但别当唯一门栓  
- **权限**：数据库账号最小权限，就算注进去也少搬一点粮
