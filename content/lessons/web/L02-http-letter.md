## 钩子

浏览器点一下「登录」，看起来像瞬移。其实中间有个信差：把你的话写成**一封信**送到客栈账房，账房再回一封。  
安全人的第一门轻功，不是打洞，是**拆信看懂**——请求行、头、体，分别写了什么。  
工具（浏览器 Network、Yakit）只是放大镜；看不懂信，放大镜也白给。

（停：等学员说「继续」）

## 片 1 · 一封请求信长什么样

记住三块就够起步：

| 部位 | 像什么 | 例子 |
|------|--------|------|
| 请求行 | 信封上的「做什么 + 寄哪」 | `GET /login HTTP/1.1` |
| 请求头 | 附言（我是谁浏览器、我带什么饼干） | `Host`、`Cookie`、`Content-Type` |
| 请求体 | 信纸正文（常在 POST） | `username=a&password=b` |

方法先混熟四个：`GET`（取）、`POST`（交）、`PUT`/`DELETE`（改/删，后面再细）。  
状态码先混三个家族：`2xx` 成了、`3xx` 跳了、`4xx` 你这边有问题、`5xx` 客栈炸了。

（停：等学员说「继续」）

## 片 2 · 为什么安全人死磕 HTTP

几乎所有 Web 漏洞，最后都落在「某一封信的某个字段被服务器误解」。  
注入、越权、伪造请求……攻击面常是：**参数、头、Cookie、路径**。  
所以入门顺序是：先会抓一封真实的信 → 再改一个字段看世界怎么变 → 再谈漏洞名字。

## 片 3 · 今天怎么动手（选一条路）

**路 A（零部署）**：打开任意登录页 → F12 → Network → 点登录 → 点开那条请求，指出请求行 / 一个头 / 有没有 body。  

**路 B（仓库示例）**：按 `labs/http-observation/README.md` 起环境，用浏览器或 Yakit 抓一次，截图或粘贴「脱敏后的」请求结构说明。

先完成「看见」，别急着改包打洞。
