# 实验策略：环境动态，目标固定

SecMentor **不是**在线课程平台。`labs/` 只是可复用示例库，**不是** topic 硬依赖。

## 一句话

> 环境实现由 Agent 按学员机器动态选择；教学目标与验收标准保持稳定。

## 必须固定的四件事

### 1. 明确今日教学目标

开实验前先说清验证哪几条能力（对齐 topic `outcomes`）。  
禁止「靶场里有 SQL 注入所以今天就随便打」。

### 2. 验证环境真实可用

`docker compose up` ≠ 成功。须让学员确认至少：

- 进程/容器在跑（或其替代环境可访问）  
- 端口或 URL 能打开  
- 能发出请求并看到可预期的一类响应  

镜像名、版本、端口、菜单路径：**不预钉死**；失效则换 DVWA / 其他学习靶 / 最小自建服务 / 学员已有环境。

### 3. 独立验收（含迁移）

走完靶场步骤 ≠ 掌握。须按 rubric 换参数/换场景做 `apply`/`transfer`，并留下非自述证据。

### 4. 合法边界

本地、仓库示例、专用靶场或明确授权目标。禁止未授权真实站。优先绑本机回环。

## Agent 选环境的顺序（建议）

1. 学员机器上**已经能用**且覆盖目标的环境  
2. 仓库 `labs/` 中 `covers` 匹配的示例（启动失败则放弃，勿死磕）  
3. 常见学习向靶场（名称现场查，不钉版本）  
4. 最小本地演示（几十行有意脆弱服务，仅本地，用完可删）

## 与 curriculum 的关系

- `curriculum.yaml` 管：outcomes、prerequisites、remediation、vertical_projects  
- **不**写 `topic → 固定 lab`  
- 一个实验可覆盖多个 outcomes；一个 outcome 也可用多种环境  

证据里可注明实际使用的环境（如 `env: labs/http-observation` 或 `env: minimal-flask`），便于复盘，不作课程解锁条件。
